Today’s goal. Model quantities that change by a fixed addition or fixed percentage, decide which input values a model permits, and connect tables, equations, and graphs. Review arithmetic/geometric sequences, then practice identifying discrete versus continuous models and solving one-step equations.
Important mathematical clarification — Discrete and continuous functions

The MVP student packet and teacher’s manual do not always distinguish consistently between which inputs a model permits and whether a quantity changes in jumps. These are different mathematical questions. This lesson uses explicit definitions and states its modeling assumptions. The smaller red notes identify specific places where MVP’s explanation needs qualification.

A separate companion explanation examines the issue in greater depth, with exact passages from both MVP books.

The MVP teacher’s notes say fractional-day inputs do not make sense because the deposit happens once per day. That is true of the chosen daily-checkpoint model, not a restriction on all possible models of the piggy bank. A count recorded at any time, including halfway through a day, is also meaningful; it stays constant between deposits and jumps when pennies are added. In this lesson the dots show the balance after whole numbers of days.

Worked comparison — Why Problems 1 and 2 are both linear.

Pennies increase by 3 for each complete day; pool water increases by 2 for each minute. Neither multiplies its current value by a fixed percentage. They have the same type of change but different allowed inputs and different physical units.

Worked comparison — Why Problems 3 and 4 are both exponential.

A bank balance is multiplied by 1.03 each month and grows. Draining water is multiplied by 0.97 each minute and shrinks. In both cases the percentage applies to the current amount, not the original amount.

CLARIFYING DEFINITIONS — Linear, exponential, arithmetic, geometric

Linear: equal additions over equal input steps (a constant rate of change). Exponential: equal multiplication factors over equal input steps. An arithmetic sequence is a linear-type rule read at separate numbered terms; a geometric sequence is an exponential-type rule read at separate numbered terms. The two distinctions—kind of change and allowed inputs—are independent.

3. SET — When a problem has not defined the function

IN YOUR MVP PACKETSection 2.1 · Set · p. 4 · Problems 10–15
The packet asks you to label each statement discrete or continuous. Several descriptions do not define a function well enough for a unique answer. The examples below show what additional information is needed.
Important mathematical problem with the original packet
MVP clarification — Section 2.1, Set, Problems 10–15

These questions ask whether a relationship is discrete or continuous without clearly defining the function to be classified. To answer mathematically, we need to know what the input represents, what the output represents, and which input values are allowed (the domain).

Several statements can support either a discrete-domain model or a model using every time value in an interval. Problem 15 does not specify a function at all. As written, these questions do not have uniquely determined mathematical answers. There is no single correct classification without adding assumptions that the packet does not state.

For the homework, state a reasonable input, output, and domain before describing your model. Another student can legitimately choose a different model. A rate such as “per day” does not by itself establish a whole-number-day domain.

CLEAR DEFINITIONS — What must be specified?

Input: the quantity you choose, such as elapsed time or day number.

Output: the quantity the function gives for each input, such as total gallons or number of laughs.

Domain: all the input values the model allows. A discrete-domain model uses separated values, such as day numbers 0, 1, 2, … . A continuous-time model allows fractional times as well. Allowing every time value does not guarantee that the output changes smoothly; counts can jump.

Worked example — MVP Set Problem 12: Water flowing over Niagara Falls

The statement gives a volume of about 3.24 billion gallons per day, but does not say what the function's input or output should be. Consider two possible models, each assuming a steady average flow.

  1. Model A — Record cumulative gallons only at the end of each day. Input: the completed day number n = 0, 1, 2, 3, … . Output: total gallons since day 0. The model is V(n) = (3.24 × 109)n. Its domain is discrete, because we have chosen whole-day checkpoints.
  2. Model B — Track cumulative gallons at any elapsed time. Input: t days, including fractions such as 0.5. Output: total gallons since the start. The model is V(t) = (3.24 × 109)t for any real t ≥ 0. Its domain includes every nonnegative real time, and the idealized volume changes continuously.

Conclusion: the same daily rate supports both choices. The statement alone does not determine which model the exercise wants.

Worked example — MVP Set Problem 13: Laughs per day

The statement says an average person laughs about 15 times per day. It does not specify whether we are recording daily totals or tracking laughter moment by moment.

  1. Model A — Daily record. Input: day number n = 1, 2, 3, … . Output: number of laughs during that day. We record one whole-number count per day, so the model has a discrete domain. The reported average of 15 does not mean every day has exactly 15 laughs.
  2. Model B — Running count. Input: elapsed time t, including fractions of a day. Output: total laughs so far. The domain includes every moment of time, but the count stays unchanged between laughs and jumps by one when a laugh occurs. That is a step function, not a smoothly changing continuous function.

Conclusion: the output being a whole-number count does not tell us which inputs are allowed. And a function defined at every moment is not automatically a continuous function.

CLARIFYING DISTINCTION — Discrete inputs are not the same as jumping outputs

A function defined only for day numbers 1, 2, 3, … has a discrete domain. A running count, defined at every instant but changing in jumps, has a continuous interval as its domain but is not a continuous function. These are different mathematical properties.

Teacher’s review of the original packet

Fundamental concern — Inconsistent criteria for “discrete” and “continuous”

The Section 2.1 teacher’s notes treat fractional-day inputs for the piggy bank as nonsensical because deposits occur once a day. Yet the Section 2.2 teacher’s notes recognize that shelving books can have a continuous time domain even though completed-book counts take only whole-number values. These are compatible modeling choices only if the input and sampling rule are stated. The notes instead alternate among the input domain, the possible outputs, and whether a process changes gradually. A student applying one explanation to another exercise is not given a consistent decision rule. See the separate companion analysis for precise passages and their locations.

Main task, Problem 1 — Distinguish daily checkpoints from an elapsed-time function

The teacher notes correctly call for separated points at whole-number days. But the physical number of pennies exists between deposits, so “the number of pennies as a function of time” is not intrinsically restricted to integer times. A whole-day snapshot model is valid, while an instantaneous count is a step function. Explicitly say which one the graph represents.

Main task, Problem 3 — Bank balance is not continuously compounded

The packet specifies interest payments at the end of each month. The ideal monthly-checkpoint model is geometric, but treating the account as continuously increasing between payments would misrepresent the stated terms. Its real-time balance is constant between postings, absent withdrawals or deposits. Amounts should also be rounded to cents in an actual bank, even if an unrounded model is useful for instruction.

Serious mathematical deficiency — Set Problems 10–15 do not specify functions

The student packet asks students to identify each statement as a discrete or continuous relationship, but generally does not provide an independent variable, dependent variable, or domain. These are not optional details: the classification depends on the mathematical model being defined. For instance, “17 trees saved per ton” leaves the meaning and permitted values of the input unresolved; “15 laughs per day” could mean a daily count or a running count defined at every instant. The description of stock prices falling 75% in Problem 15 does not define a function at all.

Consequently, these exercises do not have uniquely defensible classifications as written. This is not just awkward wording. The packet asks students to apply a mathematical classification before specifying the mathematical object to which it applies. A student can make reasonable assumptions and still produce a different answer from the one expected.

Suggested correction: For each context, state the independent and dependent variables, specify the domain, and distinguish the exact modeled quantity from daily measurements or approximations. Alternatively, explicitly ask students to propose two possible models for the same description and explain how their domains differ. Do not grade an unstated modeling assumption as though it were a mathematical error.
